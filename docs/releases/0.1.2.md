# OrbitFabric F Prime Adapter 0.1.2

`0.1.2` is a patch release that keeps the accepted `0.1` adapter behavior and exact F Prime/FPP compatibility lane unchanged while freezing a stronger public integration and reproducibility surface.

## What is new

This release adds a second public Reference Example for provider-native semantic reconciliation.

The new example reconciles explicit OrbitFabric Projection Profile and Integration Result intent against the FPP semantic model using the version-matched `fprime-python-model` API.

It checks:

```text
component and instance placement
local command / event / telemetry allocation
symbols
telemetry packet membership
generated-source provenance
```

The proof is example-owned and does not introduce a new adapter operation or stable adapter API.

The repository now provides two complementary public Reference Examples:

```text
reference-contract-evolution
    stable OrbitFabric mission identity across evolving native F Prime placement

reference-semantic-reconciliation
    explicit projected intent reconciled against provider-native FPP semantics
```

Both examples now include clean local reproduction paths over the exact supported lane.

## Repository and release boundary

The installable release artifact remains intentionally minimal:

```text
orbitfabric_fprime_adapter-0.1.2-py3-none-any.whl
```

The matching Git tag and GitHub source archive freeze the broader engineering and integration surface for the same release, including:

```text
examples/
native_acceptance/
docs/
tests/
CI workflows
```

This keeps runtime installation separate from integration examples and engineering evidence while still providing one stable release coordinate for the complete repository state.

## Reproducibility hardening

The local greenfield paths made several assumptions explicit:

- Java 11 is explicitly provisioned for the supported FPP 3.2 semantic-reconciliation lane;
- local example and native-acceptance workspaces are ignored by Git;
- exact Core Integration Input Set identity can vary with provenance-bearing filesystem paths and is not a semantic Mission Model fingerprint;
- `fprime-python-model` package version text can vary with Git checkout metadata, while the exact Git commit remains the authoritative pin for the semantic consumer.

These findings do not change adapter semantics or compatibility.
